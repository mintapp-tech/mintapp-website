# Review-only SQL (synthetic review project only)

These files are for the isolated synthetic review project (`mintapp-review`) and
nothing else. They are **not migrations**: `npm run test:db` fails if anything in
them appears in `supabase/migrations/`. Every file refuses to run unless the
database answers `review_environment() = 'synthetic-review'` (the marker in
`tests/fixtures/review-marker.sql`), which the live database never has.

| File | What it does |
| --- | --- |
| `review_tools.sql` | Installs the guarded tools: `review_purge` (dry run by default) and `review_delete`. Finds live-test rows by internal evidence: live-test email addresses and booking ids, the old fixture's fixed ids, and companies, contacts and prospects created by the three synthetic test sign-ins. Never touches Supabase Auth (reviewer accounts and their authenticators), settings (including the default reviewer), automation state or the curated seed. |
| `review_clean.sql` | Installs one function, `review_clean`, that empties the review project of its operational test data in a single transaction (dry run by default). `npm run review:clean` calls it. Needed because the API roles cannot delete from these tables. Same safety checks inside the database. Never touches Supabase Auth, settings, automation state or the marker. |
| `seed_curated.sql` | The curated, fictional review dataset: one lead in every workflow position and the complete Lotus Dental Care case with an approved Direction Pack. Generated by `npm run review:seed` from `src/lib/review-seed/data.ts`; re-running replaces the previous seed only. It does not choose a default reviewer. |

## Emptying the review project: `npm run review:clean`

For "start the review again from nothing": removes every operational test row, not only
what the live tests left (`review_purge`, below, is the narrower tool for that).

**Once**, in the SQL editor of `mintapp-review`: paste and run the whole of
`supabase/review/review_clean.sql`. It installs `review_clean`; the API roles cannot delete
from these tables, so removal has to run with the owner's rights, and this is the narrowest
way: one function, only the listed tables, only the server key may run it.

Then, from the repository (PowerShell eats the `--`; use `npm.cmd` there):

```
npm run review:clean               # dry run: the checks and the row counts, changes nothing
npm run review:clean -- --apply    # removes what the dry run listed
```

- It loads only `.env.review.local`, and refuses unless the project answers
  `review_environment() = 'synthetic-review'` and is not the project named by `SUPABASE_URL`.
- It stops before the first write if migrations 15 and 16 are missing, if a table appeared
  that it does not know, if any inquiry is not recognised as synthetic (live-test address or
  booking id, the old fixture's ids, or the curated seed), or if a company, contact or
  prospect was made by anyone but a synthetic test sign-in. `review_clean` repeats these
  checks inside the database, so calling it directly is no way round them.
- It removes the inquiry, CRM, preparation and Direction Pack rows, their notes, follow-ups,
  activity and stage history, and the sign-in throttle, children before parents. It keeps
  settings (including the default reviewer), automation switches, Supabase Auth (reviewer
  accounts and their authenticators are never read or written), the schema and the marker.
- It is **one transaction**: any failure puts everything back. A second full run removes nothing.
- It prints only table names and counts. Never a row, an address, a key or the project address.
- `tests/scripts/review-clean.test.mjs` and `tests/db/review-clean.test.mjs` cover the checks,
  the order (against the real foreign keys), the rollback, idempotency and what it never prints.
  `tests/dashboard/empty-review.spec.ts` checks the empty admin in English and Arabic.
  It does not load the seed: `seed_curated.sql` is a separate step.

## Owner-run steps (Supabase SQL editor of `mintapp-review`, in this order)

Nothing here has been run on any remote database. In the SQL editor of the review
project:

1. **Install the tools** (once, and again after they change): paste and run the whole of
   `supabase/review/review_tools.sql`.
2. **Dry run**, which changes nothing:

   ```sql
   select * from public.review_purge();
   ```

   Read the counts: live-test inquiries by evidence, the old fixture, and the prospects,
   companies and contacts created by the test sign-ins.
3. **Apply**, only if the counts match what you expect:

   ```sql
   select * from public.review_purge(p_apply => true);
   ```

4. **Load the curated seed**: paste and run the whole of
   `supabase/review/seed_curated.sql`.
5. **Choose the default reviewer** yourself in the admin Settings, if you want one.

From then on the live tests remove their own run when they finish
(`review_purge(p_apply => true, p_run => '<tag>')` through the server key), and clear
older live-test leftovers when they start.
