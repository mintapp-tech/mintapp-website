# Review-only SQL (synthetic review project only)

These files are for the isolated synthetic review project (`mintapp-review`) and
nothing else. They are **not migrations**: `npm run test:db` fails if anything in
them appears in `supabase/migrations/`. Every file refuses to run unless the
database answers `review_environment() = 'synthetic-review'` (the marker in
`tests/fixtures/review-marker.sql`), which the live database never has.

| File | What it does |
| --- | --- |
| `review_tools.sql` | Installs the guarded tools: `review_purge` (dry run by default) and `review_delete`. Finds live-test rows by internal evidence: live-test email addresses and booking ids, the old fixture's fixed ids, and companies, contacts and prospects created by the three synthetic test sign-ins. Never touches Supabase Auth (reviewer accounts and their authenticators), settings (including the default reviewer), automation state or the curated seed. |
| `seed_curated.sql` | The curated, fictional review dataset: one lead in every workflow position and the complete Lotus Dental Care case with an approved Direction Pack. Generated by `npm run review:seed` from `src/lib/review-seed/data.ts`; re-running replaces the previous seed only. It does not choose a default reviewer. |

## Owner-run steps (Supabase SQL editor of `mintapp-review`, in this order)

Nothing here has been run on any remote database. In the SQL editor of the review
project:

1. **Install the tools** (once, and again after they change): paste and run the whole of
   `supabase/review/review_tools.sql`.
2. **Dry run**, which changes nothing:

   ```sql
   select * from public.review_purge();
   ```

   Read the counts: live-test inquiries by evidence, the old fixture, and the prospects,
   companies and contacts created by the test sign-ins.
3. **Apply**, only if the counts match what you expect:

   ```sql
   select * from public.review_purge(p_apply => true);
   ```

4. **Load the curated seed**: paste and run the whole of
   `supabase/review/seed_curated.sql`.
5. **Choose the default reviewer** yourself in the admin Settings, if you want one.

From then on the live tests remove their own run when they finish
(`review_purge(p_apply => true, p_run => '<tag>')` through the server key), and clear
older live-test leftovers when they start.
